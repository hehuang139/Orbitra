# Minecraft 官方版本下载路线图

本路线图规划独立于现有 ROM 模拟器的 Minecraft 版本管理能力，不表示当前版本已经支持 Minecraft，也不承诺发布日期。首期只承诺覆盖 Mojang / Microsoft 官方版本清单仍公开的 **Minecraft: Java Edition** 版本；“各个版本”指官方清单中的 `release`、`snapshot`、`old_beta` 与 `old_alpha`，不包含已从官方撤下的文件、第三方整合包、模组加载器或非官方启动器版本。

## 产品边界

- 官方版本清单是版本发现的唯一上游；版本详情、客户端、资源索引、资源对象、库、原生库和日志配置只接受官方元数据直接声明或由其内容寻址规则推导出的官方地址。
- 本项目只缓存用户主动下载的文件，不将 Minecraft 客户端或资源提交到仓库、演示包、公共游戏库节点或项目方镜像。
- 首个里程碑只负责发现、下载、校验、离线保存和清理版本。“下载完成”不等于可以在浏览器中运行 Java 游戏，也不等于用户拥有启动授权。
- Microsoft 账号认证、游戏所有权校验和本地 Java 进程启动属于后续独立里程碑。不得要求用户输入 Microsoft 密码，不保存 OAuth 访问令牌到公共游戏库，也不提供离线账号或授权绕过。
- Bedrock Edition 没有等同 Java Edition 官方版本清单的公开历史版本下载流程。首期只展示 Microsoft Store 或对应平台商店的正式入口；只有存在公开、受支持且许可允许的官方接口后，才扩展到具体版本下载。

## 阶段 1：官方目录与版本模型

- [ ] 调研并记录当前官方版本清单、版本详情和资源服务的主机、字段、缓存行为、跨域限制、服务条款及故障策略；所有端点集中配置，不散落在界面代码中。
- [ ] 从官方 `version_manifest_v2.json` 获取版本目录，保存版本 ID、类型、发布时间、最后更新时间、详情地址和详情 SHA-1；未知类型保留原值并显示为未识别，不能静默归入正式版。
- [ ] 展示全部官方仍公开的版本，支持按正式版、快照版、Beta 和 Alpha 筛选，按版本 ID 搜索，并标出官方清单给出的最新正式版与最新快照版。
- [ ] 使用条件请求和本地缓存减少重复访问。官方网络不可用时可以查看带获取时间的缓存，但不得把缓存结果标记为已刷新。
- [ ] 定义稳定的内部标识和原始元数据快照，使同名版本、清单更新与本地下载状态彼此独立；解析未知字段时保持向前兼容。

验收：固定清单夹具覆盖四类版本、未知类型、重复 ID、无效 URL、缺失字段和清单更新；联网检查确认列表来自官方主机，并记录请求时间和实际条目数。

## 阶段 2：依赖解析与官方下载

- [ ] 解析所选版本详情，建立客户端 JAR、资源索引、资源对象、Java 库、按操作系统选择的原生库和日志配置依赖图；对规则、分类器、平台架构与继承字段采用明确的数据模型。
- [ ] 下载前计算已知总大小、可复用内容和新增空间；大小未知或浏览器无法可靠估计配额时明确提示，但仍由实际写入结果决定成功与否。
- [ ] 下载器提供逐文件和总体进度、并发上限、取消、超时与有界重试。只有确认官方服务器支持对应范围请求和校验语义后才启用断点续传，否则从单个失败文件重新下载。
- [ ] 临时文件与完成文件分离；所有必需文件校验通过后再原子提交版本状态。取消、断网、服务限流、空间不足或进程退出后，不得留下被误认为完整的版本。
- [ ] 按 SHA-1 和大小校验官方提供校验信息的文件；缺少校验信息的条目默认拒绝，确需兼容的例外必须单独评审并在界面明确降低的保证。
- [ ] 校验协议、主机、重定向目标和规范化路径，拒绝非 HTTPS、目录穿越、重复目标冲突、哈希不符及依赖图外文件；错误信息包含版本和文件类别，但不暴露账号令牌。

验收：至少选择当前正式版、当前快照版及一个 Alpha / Beta 历史版，在空白存储中完成官方依赖图下载与逐文件校验；注入断网、错误长度、错误哈希、重定向、配额不足和用户取消后均不会提交半成品。

## 阶段 3：本地版本库与生命周期

- [ ] 在浏览器 IndexedDB / OPFS、自托管服务端存储或本地伴随程序之间完成技术选型；记录单文件限制、总容量、流式写入、原子提交、跨平台路径和备份边界。
- [ ] 版本专属文件按版本隔离，资源对象和内容相同的库按哈希共享；引用计数或可重建索引保证删除一个版本不会破坏其他版本。
- [ ] 支持下载队列、暂停后的可恢复任务、版本详情、占用空间、最后校验时间，以及“校验并修复”和“删除版本”操作。
- [ ] 已完整下载的版本目录可离线打开和复查；官方目录刷新不得自动删除本地版本，官方撤下条目时保留本地数据并标记上游状态变化。
- [ ] 将 Minecraft 文件排除在现有 ROM ZIP 导入、ROM 备份和分布式公共游戏库同步之外，避免专有资源被误发布；如以后支持个人备份，必须单独定义格式、授权提示与恢复规则。

验收：两个版本共享资源时只保存一份内容；分别执行删除、校验、损坏修复和官方条目消失场景后，未操作版本保持完整且可离线识别。刷新、清理和下载并发时不出现引用丢失或状态倒退。

## 阶段 4：可选启动能力

- [ ] 评估桌面壳或本地伴随程序；浏览器页面不得声称能够直接启动 JVM。定义前端与本地进程之间经过用户确认、最小权限且可撤销的接口。
- [ ] 根据官方版本元数据选择受支持的 Java 运行时、类路径、原生库和启动参数，并对旧版参数与现代参数分别验证；运行时来源、版本、许可证和更新策略必须可追溯。
- [ ] 使用 Microsoft 官方 OAuth 流程获取授权，在系统安全存储中保存令牌并支持退出与撤销；启动前完成 Minecraft 所有权和玩家档案校验，认证失败不得降级为绕过授权的启动方式。
- [ ] 支持进程日志、崩溃诊断、内存设置和明确的运行中状态；退出后清理临时原生库，不删除游戏存档、资源包、截图或其他用户数据。
- [ ] 为不同 Java 代际和 Windows、macOS、Linux 分别建立启动兼容性记录。自动化元数据测试不能替代真实账号、真实设备和实际启动验证。

验收：另行定义目标系统和代表性版本后，从已校验文件完成授权、启动、退出及再次启动，并验证令牌撤销、Java 缺失、原生库错误和游戏崩溃路径。此阶段完成前，界面统一使用“下载版本”，不使用“安装并游玩”等承诺性文案。

## 跨阶段完成条件

- [ ] 官方来源、重定向、文件大小、SHA-1、下载时间和本地状态可审计；任何非官方 URL 都不能进入默认下载链路。
- [ ] 版本目录与下载器具有确定性夹具测试；联网测试只验证官方集成，不把下载到的专有文件提交为 CI 产物或缓存。
- [ ] 目录刷新、下载、取消、恢复、校验、修复和清理均有可观察状态，刷新页面或重启服务后不会把进行中任务误报为完成。
- [ ] 文档分别说明 Java Edition、Bedrock Edition、下载、启动、授权和离线能力，不能用“支持全部版本”掩盖官方已撤下内容或平台限制。

只有阶段 1 至 3 通过后，才可宣称“支持从官方源下载 Minecraft: Java Edition 公开版本”；只有阶段 4 在已记录平台和版本上通过后，才可宣称对应范围内能够启动和游玩。
