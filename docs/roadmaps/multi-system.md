# 多平台路线图：从任天堂经典主机到 PlayStation / PSP

目标是在现有 GBA 游戏库基础上，先支持 **GB、GBC、FC / NES、SFC / SNES**，再扩展 **PS1、PSP**，最后推进 **PS2**。GB / GBC 已接入 mGBA，FC / SFC 已接入固定的本地 FCEUmm / Snes9x 核心；未勾选项仍是后续任务。阶段顺序表示开发依赖，不承诺发布日期或所有设备上的运行效果。

现有 v1.1 可靠性与真实设备验收继续推进；v1.2 备份恢复的软件实现已交付，剩余设备与内存峰值验收按 [v1.2 详细 roadmap](v1.2.md) 追踪。每个平台的支持状态分别记录为「计划」「实验」「通过已记录环境验收」，不会因核心能编译或单个原创 ROM 通过就宣称全部浏览器、mapper 或商业游戏已支持。

## 阶段 1：多核心与多平台基础

- [x] 定义 `gba`、`gb`、`gbc` 平台标识，在游戏库、播放器和存档界面使用对应主机名称、标签与原生画面比例。
- [x] 定义 `nes`、`snes` 标识；FC 对应 NES，SFC 对应 SNES。PS1、PSP、PS2 标识在实际接入时再定义。
- [x] 将当前 mGBA 会话接口改为平台无关命名，并由调用方传入 GBA / GB / GBC 平台与动态 ROM 路径。
- [x] 抽出多核心会话适配，统一加载、暂停、重置、输入、音频、游戏内存档、即时存档、倒带、截图和释放入口。
- [x] 按平台延迟加载本地核心资源，并记录精确版本、源码、许可证和资源校验值；切换核心时释放监听器、音频、图形上下文和输入状态。
- [x] 为游戏和备份 manifest 增加平台信息；旧游戏库记录及旧版备份按 GBA 文件名兼容迁移，保留已有内容标识和关联。
- [x] 使用平台域分隔的内容 ID 隔离 GB / GBC；相同字节作为不同平台导入时不会共享游戏、电池存档或即时存档。
- [ ] 完成平台、核心与存档格式的完整版本模型，覆盖未来多核心及跨核心迁移规则。
- [x] 按 `.gba`、`.gb`、`.gbc`、`.nes`、`.sfc`、`.smc` 扩展名识别平台，并应用平台尺寸、ZIP 解压与内存限制。
- [ ] 增加文件头 / 内容识别与歧义确认，避免只依赖扩展名；后续平台接入时沿用同一验证入口。
- [x] 游戏库支持五个平台的筛选、平台标记和搜索；触屏、键盘与手柄设置按平台显示有效按键。
- [ ] 按平台和设备保存输入配置，并扩展按钮集合、双人输入、模拟摇杆及核心能力提示。

验收：已有 GBA 游戏、收藏、电池存档和即时存档在迁移、刷新、备份恢复后保持可用；迁移失败可恢复原数据。不同平台的游戏内存档和即时存档不互相覆盖，核心版本不兼容的即时存档不直接载入。仅对支持的能力显示可操作入口。

## 阶段 2：GB / GBC、FC / NES、SFC / SNES

建议实施顺序为 GB / GBC → FC / NES → SFC / SNES；完成一个平台的完整游玩与保存流程后再扩展下一个。

| 平台       | 当前状态与计划能力                                                                                 | 核心评估与专用验收                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| GB / GBC   | 已接入 `.gb` / `.gbc`、单色与彩色画面、方向键 / A / B / Start / Select、卡带存档与即时存档基础流程 | 当前自动化使用原创 MBC1 ROM 与 8 KiB 电池 RAM，验证真实 mGBA 运行、输入、存档与恢复；其他 mapper、RTC、实体设备和商业 ROM 范围仍待记录。 |
| FC / NES   | 已接入 `.nes`、单人标准手柄、游戏内存档与即时存档；双人输入待实现                                  | 固定 FCEUmm 4.2.3，校验 iNES 文件头；NES 2.0、更多 mapper、地区时序与真实设备范围仍待记录。                                              |
| SFC / SNES | 已接入 `.sfc` / `.smc`、单人 A / B / X / Y / L / R、游戏内存档与即时存档；双人输入待实现           | 固定 Snes9x 4.2.3；当前原创普通卡带样本通过，更多映射、增强芯片、真实设备和商业 ROM 范围仍待记录。                                       |

- [x] GB / GBC 复用仓库固定的 mGBA WebAssembly 版本，并加入运行时生成、可复现的原创 MBC1 测试 ROM。
- [x] GB / GBC 已覆盖导入、启动、图像、方向输入、暂停、电池存档、即时存档、`.sav` 导入导出和刷新持久化的自动化流程。
- [ ] 为 GB / GBC 补充 mapper / RTC 样本、人工音频和真实设备记录，并验证便携备份恢复及更多切换场景。
- [x] 为 FC / NES、SFC / SNES 固定浏览器核心与合法生成测试资源，并完成单人导入、启动、输入、即时存档与刷新恢复流程。
- [x] 覆盖五个平台之间切换、配置刷新、移动端布局与旧 GBA / GB / GBC 存档回归。
- [ ] 补充 FC / SFC 双人输入、更多 mapper / 增强芯片、设备断连、后台暂停和真实设备证据。
- [ ] 为桌面和移动端分别记录设备、浏览器、画面 / 音频、持续帧率、内存与存档结果；未验证的设备和 mapper / 增强芯片保持待验证。

验收：每个平台都有从空白游戏库导入到刷新恢复的自动化与人工证据，支持范围落实到测试资源和环境。RTC、特殊芯片、双人输入等单独记录，不能从主流程通过推导全部兼容。

## 阶段 3：PS1 与 PSP

在多核心基础和经典主机流程稳定后推进，建议先做 PS1，再做 PSP。两者先交付浏览器原型和资源预算，达到明确的设备与兼容性目标后再接入正式游戏库。

| 平台 | 原型与接入任务                                                                                                                     | 进入正式支持的条件                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| PS1  | 评估浏览器可用核心；按实际能力支持 BIN / CUE 等光盘格式，核对轨道引用、音轨、光盘组和换盘；接入记忆卡、数字 / 双摇杆手柄及即时存档 | 在已记录环境验证多轨读取、换盘后存档身份不变、记忆卡持久化与导入导出；说明固件需求、图形和音频限制。其他压缩光盘格式独立评估。 |
| PSP  | 评估浏览器可用核心；按实际能力支持 ISO / CSO 或自制程序格式，接入单模拟摇杆、肩键、游戏内存档与即时存档                            | 在目标设备验证资源加载、音频同步、模拟摇杆和触屏布局；记录图形后端、线程、内存及核心运行方式限制，不照搬桌面性能结论。         |

- [ ] 为光盘与大体积资源设计按需读取和缓存策略，评估 IndexedDB / OPFS 适用性及降级行为；避免把整个镜像重复复制到内存，也不简单放大 GBA 的 ZIP 限制。
- [ ] 核实候选构建的 WebAssembly、线程、SIMD、图形后端及 CPU 执行方式需求；逐项检测真实浏览器能力。若需 WebGPU，提供明确的检测与不支持提示；不假定桌面 JIT 可以直接迁入浏览器。
- [ ] 区分游戏内容标识、光盘组、记忆卡 / 存档目录和即时存档，定义备份恢复及冲突规则；多文件资源记录清单、各文件校验和与引用关系。跨核心或版本的即时存档默认不视为兼容。
- [ ] 如核心需要 BIOS / 固件，提供需求说明、用户本地选择与校验流程；仓库与公共测试包只包含可再分发资源，默认备份不包含固件。
- [ ] 记录初次加载耗时、下载大小、运行与倒带 / 即时存档内存开销、至少 10 分钟持续运行帧率、音频中断和移动端稳定性，再确定支持设备及文件上限。

验收：资源格式和固件缺失能给出具体说明；运行、保存、换盘或目录恢复有完整证据。只有通过目标浏览器和设备检查的平台进入正式支持，其他环境保持实验或待验证。

## 阶段 4：PS2

PS2 是明确的后续支持目标，首先完成独立的浏览器可行性验证。当前没有选定核心，也不承诺浏览器可达到桌面模拟器的兼容性或性能。

- [ ] 评估候选核心的许可证、维护情况、可复现构建，以及将 CPU 执行、向量单元、图形和音频运行时接入 WebAssembly / 浏览器的可行性。
- [ ] 用可再分发测试程序验证启动、连续渲染、输入、音频、记忆卡和资源释放；记录浏览器内存上限、所需图形能力、线程限制及不兼容项。
- [ ] 设计大体积光盘读取、BIOS 本地校验、双模拟摇杆、记忆卡与即时存档接口；区分可实现能力与尚未支持的外设功能。
- [ ] 在指定桌面设备完成持续运行、内存峰值和音画同步测试后，决定正式支持的最小设备 / 浏览器范围；移动端另行验收。
- [ ] 可行性通过后再发布详细实现 roadmap，接入游戏库、输入配置、备份恢复和 CI；未通过时记录阻碍与下一步实验，保留为计划或实验状态。

验收：形成可复现原型、环境要求和明确的继续 / 暂缓结论；仅加载页面或编译出 WASM 不算模拟支持。正式支持必须另有真实运行和保存流程的证据。

## 跨阶段完成条件

- [ ] 各核心来源、版本、许可证和本地修改可追溯，构建与资源可复现；不随应用分发无再分发许可的游戏或固件。
- [ ] 平台和核心切换、旧 GBA 数据迁移、存档隔离、备份恢复、损坏文件与资源不足路径纳入回归。
- [ ] 界面能够按能力展示按键、双人输入、模拟摇杆及可用功能；纯键盘与手机横竖屏可完成适用的关键流程。
- [ ] 每个平台单独记录支持格式、硬件特性、浏览器和设备结果；现有 GBA 回归保持通过，缺失验证不标记完成。

本路线图不包含云端串流、云同步或主机联机。新增主机支持不替代已有可靠性、数据备份、离线方案与辅助技术任务；如阶段评估需要调整技术方案，先更新对应 roadmap 和验收条件。
