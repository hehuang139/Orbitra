# 多平台路线图：从经典主机到街机、后续任天堂平台与 PlayStation

目标是在现有 GBA 游戏库基础上，先支持 **GB、GBC、FC / NES、SFC / SNES**，再评估 **Nintendo DS、Nintendo 3DS / New Nintendo 3DS、GameCube、Wii、Wii U**，增加有明确硬件与 ROM set 范围的 **街机** 支持，随后扩展 **PS1、PSP、Nintendo Switch、Nintendo Switch 2**，最后推进 **PS2**。GB / GBC 已接入 mGBA，FC / SFC 已接入固定的本地 FCEUmm / Snes9x 核心；未勾选项仍是后续任务。阶段顺序表示开发依赖，不承诺发布日期或所有设备上的运行效果。

现有 v1.1 可靠性与真实设备验收继续推进；v1.2 备份恢复的软件实现已交付，剩余设备与内存峰值验收按 [v1.2 详细 roadmap](v1.2.md) 追踪。每个平台的支持状态分别记录为「计划」「实验」「通过已记录环境验收」，不会因核心能编译或单个原创 ROM 通过就宣称全部浏览器、mapper 或商业游戏已支持。

## 阶段 1：多核心与多平台基础

- [x] 定义 `gba`、`gb`、`gbc` 平台标识，在游戏库、播放器和存档界面使用对应主机名称、标签与原生画面比例。
- [x] 定义 `nes`、`snes` 标识；FC 对应 NES，SFC 对应 SNES。
- [ ] 在实际接入时定义 `nds`、`3ds`、`gamecube`、`wii`、`wiiu`、`arcade`、`ps1`、`psp`、`switch`、`switch2`、`ps2` 等后续标识。New Nintendo 3DS 以 `3ds` 平台下的必需硬件档位记录，街机另需包含硬件系列与 ROM set / 核心版本。
- [x] 将当前 mGBA 会话接口改为平台无关命名，并由调用方传入 GBA / GB / GBC 平台与动态 ROM 路径。
- [x] 抽出多核心会话适配，统一加载、暂停、重置、输入、音频、游戏内存档、即时存档、倒带、截图和释放入口。
- [x] 按平台延迟加载本地核心资源，并记录精确版本、源码、许可证和资源校验值；切换核心时释放监听器、音频、图形上下文和输入状态。
- [x] 为游戏和备份 manifest 增加平台信息；旧游戏库记录及旧版备份按 GBA 文件名兼容迁移，保留已有内容标识和关联。
- [x] 使用平台域分隔的内容 ID 隔离 GB / GBC；相同字节作为不同平台导入时不会共享游戏、电池存档或即时存档。
- [ ] 完成平台、核心与存档格式的完整版本模型，覆盖未来多核心及跨核心迁移规则。
- [x] 按 `.gba`、`.gb`、`.gbc`、`.nes`、`.sfc`、`.smc` 扩展名识别平台，并应用平台尺寸、ZIP 解压与内存限制。
- [ ] 增加文件头 / 内容识别与歧义确认，避免只依赖扩展名；后续平台接入时沿用同一验证入口。
- [x] 游戏库支持五个平台的筛选、平台标记和搜索；触屏、键盘与手柄设置按平台显示有效按键。
- [ ] 按平台和设备保存输入配置，并扩展按钮集合、双人输入、模拟摇杆及核心能力提示。

验收：已有 GBA 游戏、收藏、电池存档和即时存档在迁移、刷新、备份恢复后保持可用；迁移失败可恢复原数据。不同平台的游戏内存档和即时存档不互相覆盖，核心版本不兼容的即时存档不直接载入。仅对支持的能力显示可操作入口。

## 阶段 2：GB / GBC、FC / NES、SFC / SNES

建议实施顺序为 GB / GBC → FC / NES → SFC / SNES；完成一个平台的完整游玩与保存流程后再扩展下一个。

| 平台       | 当前状态与计划能力                                                                                 | 核心评估与专用验收                                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| GB / GBC   | 已接入 `.gb` / `.gbc`、单色与彩色画面、方向键 / A / B / Start / Select、卡带存档与即时存档基础流程 | 当前自动化使用原创 MBC1 ROM 与 8 KiB 电池 RAM，验证真实 mGBA 运行、输入、存档与恢复；其他 mapper、RTC、实体设备和商业 ROM 范围仍待记录。 |
| FC / NES   | 已接入 `.nes`、单人标准手柄、游戏内存档与即时存档；双人输入待实现                                  | 固定 FCEUmm 4.2.3，校验 iNES 文件头；NES 2.0、更多 mapper、地区时序与真实设备范围仍待记录。                                              |
| SFC / SNES | 已接入 `.sfc` / `.smc`、单人 A / B / X / Y / L / R、游戏内存档与即时存档；双人输入待实现           | 固定 Snes9x 4.2.3；当前原创普通卡带样本通过，更多映射、增强芯片、真实设备和商业 ROM 范围仍待记录。                                       |

- [x] GB / GBC 复用仓库固定的 mGBA WebAssembly 版本，并加入运行时生成、可复现的原创 MBC1 测试 ROM。
- [x] GB / GBC 已覆盖导入、启动、图像、方向输入、暂停、电池存档、即时存档、`.sav` 导入导出和刷新持久化的自动化流程。
- [ ] 为 GB / GBC 补充 mapper / RTC 样本、人工音频和真实设备记录，并验证便携备份恢复及更多切换场景。
- [x] 为 FC / NES、SFC / SNES 固定浏览器核心与合法生成测试资源，并完成单人导入、启动、输入、即时存档与刷新恢复流程。
- [x] 覆盖五个平台之间切换、配置刷新、移动端布局与旧 GBA / GB / GBC 存档回归。
- [ ] 补充 FC / SFC 双人输入、更多 mapper / 增强芯片、设备断连、后台暂停和真实设备证据。
- [ ] 为桌面和移动端分别记录设备、浏览器、画面 / 音频、持续帧率、内存与存档结果；未验证的设备和 mapper / 增强芯片保持待验证。

验收：每个平台都有从空白游戏库导入到刷新恢复的自动化与人工证据，支持范围落实到测试资源和环境。RTC、特殊芯片、双人输入等单独记录，不能从主流程通过推导全部兼容。

## 阶段 3：Nintendo DS、Nintendo 3DS 与 New Nintendo 3DS

这一阶段先接入 Nintendo DS，再评估 Nintendo 3DS；New Nintendo 3DS 作为需要更高性能、C-Stick 或 ZL / ZR 的增强硬件档位单独标记。火焰纹章兼容目标包括 DS 的《新·暗黑龙与光之剑》《新·纹章之谜》，以及 3DS 的《觉醒》《if / Fates》《Echoes》；商业游戏只用于用户自有内容的兼容性记录，不随项目分发。

- [ ] 分别选择许可证清晰、可复现构建且可在浏览器运行的 DS 与 3DS 核心；记录 WebAssembly、线程、SIMD、WebGL / WebGPU、共享内存和持续运行资源需求，不从桌面版本可运行推导网页可用。
- [ ] 设计双屏显示模式，支持上下 / 左右排列、单屏放大与屏幕交换；把触控笔、麦克风、合盖和 3DS Circle Pad 等能力纳入可配置输入，缺失能力时给出明确提示。
- [ ] 按验证结果接入 `.nds` 及 3DS 内容格式，使用文件头和内容元数据识别平台；需要固件、系统档案或用户密钥时只接受本地提供并校验，不随应用、备份或测试包分发。
- [ ] 区分卡带存档、3DS SD / 扩展数据和即时存档，按平台、游戏、核心版本及硬件档位隔离；New Nintendo 3DS 专用内容不得在基础 3DS 档位被误报为兼容。
- [ ] 覆盖双屏缩放、触控坐标、键盘 / 手柄 / 移动触屏输入、音频、暂停、后台恢复、核心切换和资源释放；记录桌面与移动端的帧率、音频和内存结果。

验收：DS 与 3DS 分别使用可再分发测试程序完成导入、启动、双屏、触控、输入、音频、保存及刷新恢复。New Nintendo 3DS 档位另有能力检测与性能证据；火焰纹章目标作品只在合法的用户自有内容上记录结果，未测试作品保持未验证。

## 阶段 4：GameCube、Wii 与 Wii U

三个平台共享大体积光盘、复杂图形和系统数据问题，但输入、存档与显示模型不同，必须分别验收。火焰纹章兼容目标为 GameCube《苍炎之轨迹》、Wii《晓之女神》和 Wii U《幻影异闻录♯FE》；Wii U Virtual Console 旧作不替代对应原始平台的验收。

- [ ] 评估候选核心的许可证、WebAssembly 移植成本、CPU 执行方式、线程、SIMD 和 WebGL / WebGPU 后端；分别建立 GameCube / Wii 与 Wii U 的最小浏览器原型，记录下载体积、启动耗时和至少 15 分钟持续运行结果。
- [ ] 为光盘和多文件资源设计按需读取、校验与 OPFS / IndexedDB 缓存，避免完整镜像的重复内存复制；按实际核心能力确定 ISO、GCM、RVZ、WUD / WUX 或其他格式范围，不预先宣称未验证格式。
- [ ] 接入 GameCube 手柄、记忆卡和多控制器；为 Wii 单独设计 Wii Remote、指针、体感、Nunchuk 与经典手柄能力；为 Wii U 处理 GamePad 双屏、触控及 Pro Controller，无法映射的外设功能明确列为不支持。
- [ ] 区分 GameCube 记忆卡、Wii / Wii U NAND 与即时存档，记录地区、标题 ID、核心及系统版本；需要系统文件、固件或用户密钥时提供本地选择和校验流程，不纳入应用分发或默认备份。
- [ ] 覆盖平台切换、控制器断连、后台恢复、图形上下文丢失、音频同步、存档导入导出和资源释放；根据实际结果分别确定桌面和移动端支持范围。

验收：每个平台至少有一个可再分发测试程序完成资源导入、连续渲染、适用输入、音频、保存和刷新恢复；火焰纹章目标作品逐项记录启动、战斗画面、输入、音频和存档结果。仅能启动菜单、依赖桌面 JIT 或无法稳定释放资源不算浏览器支持。

## 阶段 5：街机

街机支持先限定首批硬件系列与游戏清单，不把单个核心能够识别的全部机板或 ROM 都视为已支持。候选核心优先评估 FinalBurn Neo 或其他可维护、可在浏览器稳定运行且许可证适合本项目的实现，选型后固定核心和 ROM set 版本。

- [ ] 通过可再分发测试资源评估候选核心的 WebAssembly 构建、许可证、体积、启动时间、持续运行性能、音频同步和移动端内存占用，确定首批硬件系列与最低浏览器 / 设备范围。
- [ ] 为 `.zip` 街机 ROM 建立独立识别流程，记录 ROM set 版本、核心版本、机板、地区和校验结果；处理 BIOS、父 ROM / 子 ROM 与多文件依赖，缺失或版本不匹配时列出具体文件，不与普通 ZIP 单 ROM 导入混淆。
- [ ] 接入摇杆、1P / 2P 开始、投币和按游戏声明的操作按钮；支持双人独立映射，并为竖屏游戏提供适用的画面旋转和触屏布局。
- [ ] 按核心实际能力接入暂停、重置、即时存档与高分 / NVRAM 持久化；存档按游戏、核心和 ROM set 版本隔离，不承诺跨核心或不兼容版本迁移。
- [ ] 建立逐游戏兼容性记录，覆盖启动、画面方向、输入、音频、持续帧率、存档与恢复；未列入首批清单的游戏和机板保持实验或未验证状态。

验收：至少一个横屏和一个竖屏的可再分发测试游戏在已记录的桌面与移动环境完成导入、启动、输入、持续运行及可用存档恢复流程；缺少 BIOS / 依赖、ROM set 不匹配和资源不足均有明确诊断。核心支持某个驱动不等于项目已验收对应游戏。

## 阶段 6：PS1 与 PSP

在多核心基础、经典主机和街机流程稳定后推进，建议先做 PS1，再做 PSP。两者先交付浏览器原型和资源预算，达到明确的设备与兼容性目标后再接入正式游戏库。

| 平台 | 原型与接入任务                                                                                                                     | 进入正式支持的条件                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| PS1  | 评估浏览器可用核心；按实际能力支持 BIN / CUE 等光盘格式，核对轨道引用、音轨、光盘组和换盘；接入记忆卡、数字 / 双摇杆手柄及即时存档 | 在已记录环境验证多轨读取、换盘后存档身份不变、记忆卡持久化与导入导出；说明固件需求、图形和音频限制。其他压缩光盘格式独立评估。 |
| PSP  | 评估浏览器可用核心；按实际能力支持 ISO / CSO 或自制程序格式，接入单模拟摇杆、肩键、游戏内存档与即时存档                            | 在目标设备验证资源加载、音频同步、模拟摇杆和触屏布局；记录图形后端、线程、内存及核心运行方式限制，不照搬桌面性能结论。         |

- [ ] 为光盘与大体积资源设计按需读取和缓存策略，评估 IndexedDB / OPFS 适用性及降级行为；避免把整个镜像重复复制到内存，也不简单放大 GBA 的 ZIP 限制。
- [ ] 核实候选构建的 WebAssembly、线程、SIMD、图形后端及 CPU 执行方式需求；逐项检测真实浏览器能力。若需 WebGPU，提供明确的检测与不支持提示；不假定桌面 JIT 可以直接迁入浏览器。
- [ ] 区分游戏内容标识、光盘组、记忆卡 / 存档目录和即时存档，定义备份恢复及冲突规则；多文件资源记录清单、各文件校验和与引用关系。跨核心或版本的即时存档默认不视为兼容。
- [ ] 如核心需要 BIOS / 固件，提供需求说明、用户本地选择与校验流程；仓库与公共测试包只包含可再分发资源，默认备份不包含固件。
- [ ] 记录初次加载耗时、下载大小、运行与倒带 / 即时存档内存开销、至少 10 分钟持续运行帧率、音频中断和移动端稳定性，再确定支持设备及文件上限。

验收：资源格式和固件缺失能给出具体说明；运行、保存、换盘或目录恢复有完整证据。只有通过目标浏览器和设备检查的平台进入正式支持，其他环境保持实验或待验证。

## 阶段 7：Nintendo Switch 与 Nintendo Switch 2

Switch 系平台首先进行独立可行性研究，不把桌面模拟器、向后兼容或单个自制程序可启动视为网页支持。火焰纹章兼容目标包括 Switch 的《风花雪月》《Engage》及相关移植 / 衍生作，以及 Switch 2 的《Fire Emblem: Fortune's Weave》；Switch 2 必须作为独立硬件目标评估。

- [ ] 核实候选核心的许可证、维护状态、可复现构建和浏览器移植边界，重点验证 CPU 执行、线程、SIMD、WebGPU、内存上限、着色器缓存和音频后端；无法在浏览器内合法、稳定运行时保留为研究状态。
- [ ] 用可再分发自制程序建立最小原型，记录首次加载、持续帧率、峰值内存、图形正确性、音频同步、暂停恢复及资源释放；Switch 与 Switch 2 分开形成继续 / 暂缓结论。
- [ ] 原型通过后再确定游戏资源格式、按需读取和缓存方案；系统文件、固件和用户密钥只允许本地选择与校验，不随应用、备份或测试资源分发，也不提供规避平台保护的内容获取流程。
- [ ] 接入 Joy-Con、Pro Controller、掌机 / 底座模式与触控等核心已实现能力；Switch 2 的新增输入和系统能力依据公开规格及实际核心支持另行声明，不从 Switch 支持状态继承。
- [ ] 按标题 ID、用户档案、平台、核心和系统版本隔离游戏存档与即时存档，定义升级、备份恢复和不兼容诊断；商业火焰纹章作品仅通过用户自有内容记录兼容性。

验收：每个平台都需有可复现浏览器原型、合法测试资源、环境要求和明确的继续 / 暂缓结论。正式接入还要求在指定设备完成导入、持续运行、输入、音频、保存与刷新恢复；只有核心编译成功或显示首帧不算支持。

## 阶段 8：PS2

PS2 是明确的后续支持目标，首先完成独立的浏览器可行性验证。当前没有选定核心，也不承诺浏览器可达到桌面模拟器的兼容性或性能。

- [ ] 评估候选核心的许可证、维护情况、可复现构建，以及将 CPU 执行、向量单元、图形和音频运行时接入 WebAssembly / 浏览器的可行性。
- [ ] 用可再分发测试程序验证启动、连续渲染、输入、音频、记忆卡和资源释放；记录浏览器内存上限、所需图形能力、线程限制及不兼容项。
- [ ] 设计大体积光盘读取、BIOS 本地校验、双模拟摇杆、记忆卡与即时存档接口；区分可实现能力与尚未支持的外设功能。
- [ ] 在指定桌面设备完成持续运行、内存峰值和音画同步测试后，决定正式支持的最小设备 / 浏览器范围；移动端另行验收。
- [ ] 可行性通过后再发布详细实现 roadmap，接入游戏库、输入配置、备份恢复和 CI；未通过时记录阻碍与下一步实验，保留为计划或实验状态。

验收：形成可复现原型、环境要求和明确的继续 / 暂缓结论；仅加载页面或编译出 WASM 不算模拟支持。正式支持必须另有真实运行和保存流程的证据。

## 跨阶段完成条件

- [ ] 各核心来源、版本、许可证和本地修改可追溯，构建与资源可复现；不随应用分发无再分发许可的游戏或固件。
- [ ] 平台和核心切换、旧 GBA 数据迁移、存档隔离、备份恢复、损坏文件与资源不足路径纳入回归。
- [ ] 界面能够按能力展示按键、双人输入、模拟摇杆、双屏、触控、指针 / 体感及可用功能；纯键盘与手机横竖屏可完成适用的关键流程。
- [ ] 大体积资源按需读取、缓存、存储配额、清理和备份策略按平台验收，导入失败或空间不足不会留下不可见的孤立数据。
- [ ] 每个平台单独记录支持格式、硬件特性、浏览器和设备结果；现有 GBA 回归保持通过，缺失验证不标记完成。

本路线图不包含云端串流、云同步或主机联机。新增平台支持不替代已有可靠性、数据备份、离线方案与辅助技术任务；如阶段评估需要调整技术方案，先更新对应 roadmap 和验收条件。
